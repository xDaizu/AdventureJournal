# tools

Local checks for AdventureJournal, since the game can't run here. This folder lives **inside the addon folder** (`AdventureJournal/tools/`), so it travels with the addon's repository. The game never loads it: no TOC lists these files. Leave it out of release zips (M8).

```
cd AdventureJournal/tools
npm install          # once
npm test             # Lua 5.1 syntax check + scenario comparison
npm run update-expected   # accept a deliberate behaviour change
```

- `check-syntax.js`: parses every `.lua` file in the addon folder as Lua 5.1 (`luaparse`; `node_modules` and `.git` skipped). Catches `goto`, `//` and other 5.2+ syntax. Extra folders can be passed as arguments; in the wow-addons workspace, `node check-syntax.js ../../AJProbe` also checks the dev probe.
- `run.js`: runs AdventureJournal under `fengari` with stubbed WoW globals (`lua/stubs.lua`) and renders a report per run: scenario notes, registered events, globals the addon created, chat output, and the full `AdventureJournalDB`. Every scenario runs once per client flavor (`classic`, `forever`, loading the files listed in that flavor's TOC), in up to three modes, each on top of the saved data of the previous one: a fresh login, a `/reload` (continues the jornada), and a second real login (new jornada). The scenario reads the mode from `H.mode`.
  - `lua/scenario_adventurejournal.lua`: normal play (the M0 smoke test, scripted). Reports: `expected/adventurejournal_<flavor>.txt`.
  - `lua/scenario_migration.lua`: a hand-written schema v1 diary (as saved before M4) loaded by the current code; checks that jornadas are untouched and `visited` is seeded. Reports: `expected/adventurejournal_migration_<flavor>.txt`.
  - `lua/scenario_secrets.lua`: the same kind of session with secret values, inside an instance (secret NPC name, whisper sender and text, loot message, boss names, quest ID, zone text), plus a handler that fails, `/diario diag` and `/diario debug`. Reports: `expected/adventurejournal_secrets_<flavor>.txt`.
  - `lua/scenario_options.lua` (M5): every option changed through the options panel (the scenario sets the stub check boxes and calls their `OnClick`, as the game would; on the Classic flavor `GetChecked()` returns `1`/`nil` to catch comparisons with `true`) and through the slash commands; each option changing behaviour (types dropped, dedupe unchanged across an off/on switch, secret payloads with types on and off, chat echo, mood in the book, an entry without a mood); persistence across `/reload` and a second login; the Forever TOC's `AddonCompartmentFunc` read from the TOC and called; `/diario debug demo` leaving the real diary untouched. Reports: `expected/adventurejournal_options_<flavor>.txt`. Variants of the same scenario: `_nosettings` (no `Settings` API: slash commands only, and `/diario debug buttons`), `_opentoobject` (`Settings.OpenToCategory` silently ignores a numeric ID, so the second attempt with the category object is needed).
  - `lua/scenario_bigdiary.lua` (M5): a generated schema v2 diary of 250 jornadas × 20 entries (settings from before M5, half the jornadas without a mood) loaded, opened, refreshed, scrolled and clicked. It **fails** if the ScrollBox index creates more than 80 frames, and reports the frame counts. The report omits the DB dump (`H.noDump`). Variants: `_noscrollbox` (the functions are missing), `_notemplates` (the functions exist but `WowScrollBoxList` / `MinimalScrollBar` do not), both ending on the button index (one Button per jornada: the pre-M5 behaviour, reported, not failed).
  - `lua/scenario_import.lua` (M4b), in four variants set by the scenario entry's `variant` (read as `H.variant`): `empty` (a diary with no jornadas against a synthetic `AJProbeDB` with a partial session, logins, reloads, loading screens, duplicates, secret records, another character's records, other players' loot, malformed records and chat; dry run, import, second run byte-identical, uncached loot cached later, conversations off then on, the book's two views), `overlap` (a diary whose jornadas overlap the log: live entries for the same events, a pre-M4 pair split by a reload, a session with no jornada, the current jornada; every existing entry and jornada is checked byte for byte afterwards; a type switched off is not imported and leaves `visited` alone), `noprobe` (AJProbe missing, a string, empty, only another character, an unreadable player name), `notimetable` (a client where `time{...}` ignores its table). Every run asserts that `AJProbeDB` is byte-identical afterwards and that entries stay in time order. Reports: `expected/adventurejournal_import_<variant>_<flavor>.txt`. The fixture builder, `lua/fixture_ajprobe.lua`, writes records in the shape `AJProbe.lua` writes them (from its code, not copied from a real file).
  - `lua/scenario_conversations.lua` (M4b): the live opt-in conversation log in three modes (login, `/reload`, second login): off by default (nothing registered, captured or shown; the CHAT entry still works), switched on through the options panel, every channel and relationship (group, raid, friend, Battle.net friend, me, strangers), secret text, author, GUID and language, an instance, the addon's simulated secrets, the per-day limit, paging in the book, off by command and by the panel, persistence across `/reload` and a second login. Also with `stub: 'nosocial'`. Reports: `expected/adventurejournal_conversations[_nosocial]_<flavor>.txt`.
  - `lua/scenario_newtypes.lua` (M6), variants `live` (login, `/reload`, second login), `secrets`, `off_with` / `off_without`: the five new entry types fired through their game events (level-up; system messages for party joins and leaves, learned spells; faction messages; skill messages; `GROUP_JOINED`), with dedupe windows, thresholds, unreadable and non-string payloads, a type switched off and on again, `/diario diag mensajes`; `secrets` repeats them with stub secrets in an instance and with the addon's simulated secrets. `off_with` fires the new events with every new type switched off and `off_without` does not; **`run.js` fails unless the two saved diaries are byte-identical** (`sameDiaryAs`): with every new type off the diary behaves exactly as in M4b. Also run with `stub: 'nomessages'` (none of the message strings exist: nothing matches, no error). Reports: `expected/adventurejournal_newtypes[_secrets|_nomessages|_off_with|_off_without]_<flavor>.txt`.
  - `lua/scenario_importnew.lua` (M6), variants `types` and `off_with` / `off_without`: `/diario importar` against a synthetic `AJProbeDB` with the record shapes seen in the real files (system messages with names, `GROUP_JOINED` with and without the instance category, faction messages in each client's wording, skills, spell links incl. the esES word `facultad`). Checks: dry run, import, a second run byte-identical, records already in the diary as live entries are duplicates and the existing entries are untouched, the first reputation gain per jornada across two jornadas, each new type switched off in turn on a fresh diary (not imported, arrives when switched on, repeat adds nothing), every live event compared field by field and by prose with its imported twin, and the same off-equality as above. Reports: `expected/adventurejournal_importnew_*_<flavor>.txt`.
  - `lua/scenario_chemadiary.lua` (T1): diaries written by Chema's Forever line (`1.1.0-Forever`, github.com/xDaizu/AdventureJournal `main` at `fa20e9f`). The fixture is hand-written in the shape his code saves (from reading his `Events.lua`, not from a real file): `version = 2`, `visitedZones` / `knownMounts` / `knownAchievements`, no `settings`, `mainZone`, entries of his types (`QUEST_ACCEPT`, `REVISIT`, `MOUNT`, `ACHIEVEMENT`, `GUILD`) with `header`, `travelMethod`, `npc`, `killer`. Variant `chema` (login, `/reload`, second login): the clásico profile is applied once and a later change by the player survives; his places are not discovered again; the types his diary never had are not logged; epic loot is, rare loot is not; the book shows his jornadas; `AdventureJournal_Toggle()`, `/ajdiag` and `/diario hoy ` with a trailing space work; **the run fails** if his three tables or any of his jornadas differ by one byte afterwards. Variant `roundtrip`: one of this line's diaries after the player used his version again (`version` back to 2, a place added to `visitedZones`, a jornada of his): no profile is applied, the player's settings stay, the place is merged; also `ns.ApplyProfile` both ways and hand-edited `lootQuality` / `profile` values. Reports: `expected/adventurejournal_chemadiary[_roundtrip]_<flavor>.txt`.
  - `lua/scenario_prose.lua` (T2): renders every template of every entry type (named and unnamed variants, both `groupEvent` / `repEvent` / `skillEvent` kinds, every travel method) for both sexes and checks it for a leftover brace or `%s`, `nil`, `..`, `. .`, a doubled space, a lower-case start or a lower-case letter after a full stop; also the mood lists (20 each, no final stop), the variant counts (Chema's 20 / 10), determinism, the gender pair and `ns.PlayerIsFemale` with a secret, failing or missing `UnitSex`.
  - `lua/scenario_t4a.lua` (T4a), variants `live` (login, `/reload`, second login), `secrets`, `off_with` / `off_without`: quest accepted (with a giver, without, a stale giver, a duplicate, an unreadable payload, both clients' payload shapes), revisits with every travel method (hearthstone, mage teleport, taxi, a cast that expires, someone else's cast, a spell that is no travel), the enemy named in a death (a hostile mob, a player, a non-hostile, no target, combat ending alive, combat ending in death, a secret name), guild joins and leaves (the player's own, someone else's, an invitation, an error, a player link). `off_with` / `off_without` must save the same diary (the M6 off-equality rule). The guild strings in `stubs.lua` are **invented**.
  - `lua/scenario_t4b.lua` (T4b), variants `live` (login, `/reload`, second login), `secrets`, `off_with` / `off_without`, run on **both** flavors: on Forever the mount journal is read and seeded (a Chema key kept, a second loading screen changing nothing, an event before the journal has data, a mount learned while the type is off), `NEW_MOUNT_ADDED` and `ACHIEVEMENT_EARNED` with known, unknown, secret and non-numeric values and `alreadyEarned`; on Classic Era the APIs are absent: the types are hidden, `/diario tipos montura on` is refused, the events are reported as unknown and nothing is logged. Off-equality as in M6.
- Stub options: a scenario entry in `run.js` can set `stub: 'flag,flag'`, read by `lua/stubs.lua` as `STUB.flags`: `nosettings`, `opentoobject`, `noscrollbox`, `noscrolltemplates`, `nosocial` (no `C_FriendList` / `C_BattleNet`), `notimetable` (`time{year=...}` returns the clock), `nomessages` (M6: none of the message globals `ERR_JOINED_GROUP_S`, `FACTION_STANDING_*`, `ERR_SKILL_*`, `ERR_LEARN_*` exist). The stub also provides `UnitGUID`, a group (`STUB.group`, `STUB.raid`), friends and Battle.net accounts (`STUB.friends`, `STUB.bnGameAccounts`, `STUB.bnAccounts`), and `time(table)`. `ONLY=<regex> node run.js` runs just the matching scenarios.
- `expected/`: the accepted reports. `--check` fails on any difference and writes `actual_<scenario>_<flavor>.txt` for diffing (git-ignored).
- `driver.lua` also scans the saved data after each run and **fails the run** if a secret value (a stub secret or an addon-simulated one) is in `AdventureJournalDB`.

- `import-dryrun.js` (M4b; M6 adds `--player Name-Realm`, and by default uses the character key that appears most often in the log, so a Forever file works): **read-only** rehearsal of `/diario importar` on real files, outside the game: `node import-dryrun.js --probe <AJProbe.lua> --diary <AdventureJournal.lua> [--flavor classic|forever] [--tz <zone>]`. It loads copies into the stubbed addon in memory, fires a login, runs the dry run, the import (conversations off, then on) and the repeat, and prints counts only (never an entry's text or a chat line). It opens no file for writing and checks that `AJProbeDB` is unchanged. Use the zone the game ran in (the default is this machine's). It is the way to check a real Forever file before importing in game. Example (Classic Era): `--probe "D:\Games\Battle.net\World of Warcraft\_classic_era_\WTF\Account\<ACCOUNT>\SavedVariables\AJProbe.lua" --diary "D:\Games\Battle.net\World of Warcraft\_classic_era_\WTF\Account\<ACCOUNT>\Zandalar Tribe\Volgajin\SavedVariables\AdventureJournal.lua"`.
- `ajprobe_summary.py`: read-only. Summarises AJProbe's `AJProbe.lua` (newest Forever file by default, `--flavor classic`, or a path) as Markdown for REFERENCE_SAMPLES: environment, missing APIs, failed events, loot format, secret fields per event. Never prints conversation text. See [M3_RUNBOOK.md](../M3_RUNBOOK.md).

## Secret values in the stubs

`STUB.SECRET` (a secret string) and `STUB.SECRET_NUMBER` are tables whose metatable errors on arithmetic, `#`, indexing, calling, concatenation, `<`/`<=`, `tostring` and `string.format("%s")`. The string library rejects them (not a string). `issecretvalue()` recognises them, `type()` reports `"string"` / `"number"` like the game, and `tonumber()` errors on them. `STUB.MakeSecret(kind)` makes more. The scenario's first lines check each of these behaviours.

What the stub **cannot** reproduce, so review by reading the code as well:

- `==` / `~=` between a secret and a plain value of the same type errors in the game. Lua only calls `__eq` when both operands are tables, so the stub does not error. Comparing a secret **before** calling `ns.IsSecret` is the most likely bug and the stub will not catch it by itself.
- A secret used as a table key works in the stub (a table can always be a key); the game errors.
- `string.format` / `..` return a secret string in the game; here they error. The stub is stricter, which is safe but not identical.
- The addon's own simulated secrets (`/diario debug secrets`, used on Classic Era) are proxy tables, so `type()` on them returns `"table"`, not `"string"`. Always call `ns.IsSecret` before relying on `type()`, as the guards do.
- Which values are really secret on Forever is unknown until M3. The scenario assumes the worst case.

## What the M5 stubs cannot verify

The stubs record calls; they do not render. Passing here says the addon **calls** the Settings and ScrollBox APIs the way the stub (modelled on the documented Mainline behaviour) accepts, not that the game agrees. Specifically:

- **Layout and looks**: where the panel's widgets sit, whether the 7 check boxes and the notes fit the Settings canvas, the ScrollBox row width, the scroll bar next to the parchment, fonts, colours. All `SetPoint` / `SetSize` calls are no-ops.
- **Real template names and contents**: the stub knows a fixed list of templates (`BackdropTemplate`, `UIPanelButtonTemplate`, `UIPanelCloseButton`, `UIPanelScrollFrameTemplate`, `UICheckButtonTemplate`, `InterfaceOptionsCheckButtonTemplate`, and, unless disabled, `WowScrollBoxList` and `MinimalScrollBar`) and errors on any other name. The real clients were checked for those names only through `/diario diag` on Classic Era. Nothing is known about Forever.
- **`Settings.*` signatures**: only `RegisterCanvasLayoutCategory(frame, name)`, `RegisterVerticalLayoutCategory`, `RegisterAddOnCategory(category)` and `OpenToCategory(id or category)` are stubbed. The other helpers exist in the stub but raise an error if used. Whether the real `OpenToCategory` takes an ID on a given client is exactly what the stub's two variants guess at.
- **ScrollBox physics**: the stub creates `visible rows + 1` (15) row frames, recycles them on `SetDataProvider`, and re-initialises them when the test calls `STUB.ScrollStubTo`. It does not model extent, padding, scroll bar behaviour, mouse wheel, or retaining the scroll position (`SetDataProvider`'s second argument is accepted and ignored).
- **Frame counts** in the big-diary report count the stub's `CreateFrame`, `CreateFontString` and `CreateTexture` calls, which is a good measure of "bounded", not of memory or frame time.
- `AddonCompartmentFunc`: the harness reads the TOC line and calls the function. Whether Forever shows the entry, uses `IconTexture`, and passes the arguments the function expects is untested.
- `CheckButton:GetChecked()` returns `1`/`nil` on the Classic flavor and booleans on Forever in the stub; the real return value on either client was not observed.

## What the M4b stubs cannot verify

- **The real AJProbe file.** The fixtures follow AJProbe's code (record fields, `Snap` markers, `Name-GetRealmName()` keys). `import-dryrun.js` run on a copy of the real Classic Era files (94 activity records, 4 chat lines, 11 jornadas) agreed with them, but a Forever file has not been seen: real `ENCOUNTER_END` / `BOSS_KILL` payloads, secret markers per field, Forever's loot messages and quality values are **verify in M3**.
- **Real chat events.** The stub fires `CHAT_MSG_*` with the arguments laid out as documented (text 1, author 2, language 3, GUID 12, Battle.net sender ID 13). It does not prove that `C_FriendList.IsFriend(guid)` or `C_BattleNet.GetGameAccountInfoByGUID(guid)` answer as the stub does (only `rel = "me"` has been seen in AJProbe's real data), that an author arrives with the realm in every case, or what is secret inside instances on Forever.
- **Real timestamps and time zones.** The stub runs in UTC with a fixed clock. The game's `date()` / `time{...}` and the import's matching of saved local-time strings to epochs depend on the client's time zone; the `notimetable` scenario only proves the fallback. A change of time zone or daylight saving between recording and importing can shift a jornada's range by an hour (the tolerance is 3 s); entries then fall into a new jornada rather than being lost, and duplicates are still caught by type, subject and the entries' own timestamps.
- **Layout.** The conversations button, the page buttons (`< Antes`, `Después >`) and the longer options text are positioned with `SetPoint` calls the stub ignores: whether they overlap anything in the 780 × 545 book or fit the options canvas is **verify in game** (Classic Era first, then Forever).
- **Volume.** The harness imports dozens of records. A real log can hold 50,000 activity records and 30,000 chat lines; the import loops over them once (plus a scan of the jornadas for each entry it adds) and has not been timed in the game.

## What the M6 stubs cannot verify

- **The wording of the game's strings on a real client.** `stubs.lua` defines the message globals in esES. The sentences for a party join, leave, leaving, disbanding, learning a spell or an ability (`facultad`), a skill going up or being gained, and the two reputation increases (Classic Era and Forever word them differently) are the ones AJProbe recorded; that is evidence for the *sentence*, not for the *global's name*. The names `ERR_JOINED_GROUP_S`, `ERR_LEFT_GROUP_S`, `ERR_LEFT_GROUP_YOU`, `ERR_SKILL_UP_SI` and `ERR_SKILL_GAINED_S` are on Warcraft Wiki; the rest are from memory and some are found by a prefix scan of `_G`. If a name is wrong the type silently matches nothing on that client: `/diario diag mensajes` shows it.
- **Never captured, so invented in the stubs:** the "standing changed" sentence (`FACTION_STANDING_CHANGED`; one wording per flavor, the Forever one positional to test argument order), the raid add/remove strings and the passive-ability string. Only their *shape* is tested.
- **Secret messages.** The stubs make `CHAT_MSG_SYSTEM` / `_SKILL` / `_COMBAT_FACTION_CHANGE` secret when the scenario says so. Whether Forever really does inside instances, in combat (reputation arrives during combat) or in the open world is unknown (**verify in M3**, runbook 3d).
- **Event timing and arguments.** `PLAYER_LEVEL_UP`'s first argument is assumed to be the new level (documented); `GROUP_JOINED`'s category 2 for an instance group is assumed (`LE_PARTY_CATEGORY_INSTANCE`). AJProbe saw only category 1.
- **Real volume.** A first Forever session holds 165 XP lines and 43 skill lines; the import was rehearsed on those (see `import-dryrun.js`), not timed in the game.
- **The options panel with twelve types** is laid out in two columns with `SetPoint` calls the stub ignores: whether the second column fits the Settings canvas is **verify in game**.

## What the T1 stubs cannot verify

- **A real diary from Chema's version.** The fixture follows his code; no real `AdventureJournal.lua` saved by `1.1.0-Forever` has been seen here. Before trusting the migration on a real character, back up that file and load it once in game (`/diario diag` says "Diario de la versión de Chema: sí" and how many places, mounts and achievements it kept).
- **His version reading our diary.** The round trip simulates what his `EnsureDatabase` does to one of our diaries (from reading it); running his addon on it was not tried.

## What the T2 stubs cannot verify

- **How the prose reads.** The harness checks punctuation and placeholders, not style, rhythm or whether a sentence repeats too often in one jornada. Only reading the book tells.
- **`UnitSex` on Forever.** The stub returns what the scenario sets. The API is old and documented (1 unknown, 2 male, 3 female); confirm with `/dump UnitSex("player")`.
- **Gender of other people.** Only the player's own sex is handled. Sentences about other characters (NPC, group members, bosses) avoid gendered words on purpose.

## What the T3 stubs cannot verify

- **The layout.** Widgets are stubs: nothing is drawn, sizes and anchors are not checked, so overlap (the title-bar controls, the conversations controls on the page title row, the subtitle under an index button) and clipping are only visible in game. Compare with Chema's screenshots.
- **Row spacing.** The stub's `CreateScrollBoxListLinearView` records the `spacing` argument; whether both clients honour it (24 px button + 24 px = 48 px) is not tested. If rows overlap, the fix is a 48 px element with the button created inside.
- **Textures.** `Textures/tiled.tga` is never loaded; a path typo would show as a missing (green) texture.

## What the T4a stubs cannot verify

- **The guild strings.** No `ERR_GUILD_*` message has been recorded on either client; the stub's Spanish wording is invented, and the parser classifies by the global's name. `/diario diag mensajes` in game shows the real names and round-trips a sample of each.
- **Classic Era's `QUEST_ACCEPTED`.** The `(questLogIndex, questID)` payload is from Warcraft Wiki; the Classic scenario sends it, but no real Classic record has been seen.
- **Spell IDs.** `ns.TRAVEL_SPELLS` is a short list written from memory of the vanilla spells. Whether a cast reaches `UNIT_SPELLCAST_SUCCEEDED` with that ID (and before the loading screen), and whether other teleports exist on Forever, needs a cast in game with `/diario debug on`.
- **Secrets and ordering.** Whether `UnitName("target")` and `UnitIsPlayer` are secret in instances, and the order of `PLAYER_DEAD` and `PLAYER_REGEN_ENABLED` at death, are properties of the clients. The handlers survive both orders and any secret; what the entry says in each case is what the stubs cannot tell.

## What the T4b stubs cannot verify

- **Payloads and timing.** The `NEW_MOUNT_ADDED(mountID)` and `ACHIEVEMENT_EARNED(achievementID, alreadyEarned)` payloads are from Warcraft Wiki; neither has been seen on Forever. Whether `NEW_MOUNT_ADDED` also fires for mounts the player already has (the seed assumes it might) is unknown.
- **`GetAchievementInfo`.** The stub returns `id, name, points, completed`; the real return order on Forever is unverified (an ID that is no achievement returned nothing). The code tolerates the name being first or second.
- **When the journal has data.** The stub's journal is ready at once. On a real login `GetMountIDs` may be empty at first; the seed tries at 5 s and 30 s after a loading screen and then waits for the next one.

Limits: fengari is Lua 5.3, so some runtime differences from WoW's Lua 5.1 slip through (number formatting such as `3.0`, integer division). The stubs only cover the APIs the addon uses; a missing stub shows up as "attempt to call a nil value". Passing here does not replace an in-game test.
